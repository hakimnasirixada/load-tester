# LOAD TESTER & BENCHMARKING GUIDE

This guide explains how to test the application, how k6 and the built-in simulator work, and how the target traffic profiles operate with the PostgreSQL database.

---

## 1. TRAFFIC PROFILE TARGETS

The load testing suite is calibrated for high concurrency:

- **Peer Users (Read-Heavy)**:
  - Target: **500 – 700 requests/sec (RPS)**
  - Endpoints:
    - `GET /api/feed?page=1&limit=20` (Paginated feed with cache-aside)
    - `GET /api/users/:id` (User profiles from 7,000 pre-seeded pool)
    - `GET /api/records/:id` (Record lookups from 10,000 items)
    - `GET /api/search?q=Engineering` (Search queries)

- **Admin Users (Heavy Writes & PostgreSQL Script Persistence)**:
  - Target: **100 – 200 requests/sec (RPS)**
  - Endpoints:
    - `POST /api/scripts` (**Writes actual benchmark scripts to PostgreSQL**)
    - `GET /api/scripts` (Queries saved scripts from PostgreSQL)
    - `POST /api/admin/bulk-upload` (Ingests 50 records in batch, invalidates cache)
    - `POST /api/admin/reports/generate` (CPU-intensive digest computation, async queue)
    - `GET /api/admin/audit` (Queries PostgreSQL audit logs)

---

## 2. HOW TO RUN THE SERVER

Start the backend server:

```bash
npm start
```

Once running:
- **Web Dashboard**: http://localhost:3000
- **Live Metrics (JSON)**: http://localhost:3000/metrics
- **Health Check**: http://localhost:3000/health

---

## 3. HOW TO TEST (CHOOSE YOUR OPTION)

### Option A: Using Grafana k6 (Recommended for Full Benchmarking)

The `k6/test-script.js` script has been updated with:
- `peer_traffic` scenario ramping to **500 - 700 RPS**
- `admin_traffic` scenario ramping to **100 - 200 RPS**
- Includes direct writes to the PostgreSQL `scripts` table (`POST /api/scripts`)

#### 1. Install k6 (if not already installed):
- On Windows using Winget:
  ```powershell
  winget install k6 --source winget
  ```
- Or with Chocolatey:
  ```powershell
  choco install k6
  ```

#### 2. Run the k6 Test:
```bash
npm run test:k6
```
Or directly:
```bash
k6 run k6/test-script.js
```

---

### Option B: Using the Built-In Node.js Simulator (Zero Installation Needed)

If k6 is not installed on your system, run the native load generator while the server is active:

```bash
node src/simulator.js
```

What it does:
1. Runs for 30 seconds.
2. Generates ~600 RPS for peer requests.
3. Generates ~150 RPS for admin tasks, including writing test scripts to PostgreSQL.
4. Outputs p50, p95, p99 latency percentiles and request counts in your terminal.

---

### Option C: Using the Web Frontend Dashboard (Visual Testing)

Open **http://localhost:3000** in your web browser:

1. **Live Endpoints Tab**:
   - Displays real-time request counts and percentage share for each route.
   - Adjust the refresh interval (1s live, 3s, 5s, 5 min, 10 min, or manual).
   - Test any route individually using the "Send 1x" button.

2. **Traffic Generator Tab**:
   - Click **"⚡ Send 100 Peer Requests"** to send concurrent feed and user requests.
   - Click **"📦 Trigger Admin Bulk Ingest"** to batch-insert 50 records.
   - Click **"📑 Queue Admin Report Job"** to test background CPU tasks.

3. **PostgreSQL Scripts Database Tab**:
   - Write new load testing scripts directly into PostgreSQL using the UI editor.
   - Preload k6 test templates with a single click.
   - View, search, and delete saved scripts from PostgreSQL.
